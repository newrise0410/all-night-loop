# 지시서 (SPEC)

> 이 파일은 **사람이 쓰고 루프는 읽기만** 한다.
> 작성법: `.claude/skills/all-night-loop/reference/spec-writing.md`

## 0. 목표

<!-- 한 문단. 이 프로젝트가 "끝났다"고 말할 수 있는 상태를 서술한다. -->
예) 사내 링크 단축 서비스의 API 서버를 완성한다. 생성/조회/통계 3개 엔드포인트가
동작하고 테스트가 전부 통과하면 끝이다.

## 1. 합격 기준

모든 작업은 아래를 전부 만족해야 커밋할 수 있다.

- [ ] `<검증 명령 1>` 통과 (예: `npm test`)
- [ ] `<검증 명령 2>` 통과 (예: `npm run lint`)
- [ ] 변경된 동작에 테스트가 있다
- [ ] diff 200줄 이하 (넘으면 작업을 더 쪼갠다)
- [ ] **다른 사람이 리뷰해도 통과시킬 수준인가?**
      — 디버그 출력·주석 처리된 코드·임시 이름·미해결 TODO 없음

## 2. 참조 파일

> 루프는 **작업을 고른 뒤** 이 목록 중 그 작업에 필요한 것만 연다.
> 항목별로 "언제 필요한지"를 적어두면 불필요한 읽기를 줄일 수 있다.

**반드시 읽을 것**
- `<경로>` — <왜 읽어야 하는지 / 어떤 작업일 때 / 어디까지>

**수정 금지**
- `<경로>` — <이유>

**읽지 말 것** (컨텍스트 낭비)
- `node_modules/**`, `dist/**`, `<기타>`

## 3. 규칙 (+ 왜)

- <규칙>
  → **왜**: <이유>
- 새 의존성을 추가하지 않는다
  → **왜**: 새벽에 추가된 패키지는 아무도 검토하지 않는다.
- SPEC에 없는 리팩터링을 하지 않는다
  → **왜**: 감시자가 없을 때 번진 스코프는 아침에 되돌릴 수 없다. 제안은 BACKLOG에만.
- 되돌리기 어려운 조작(push / --force / reset --hard / 마이그레이션)을 하지 않는다
  → **왜**: 사람이 깨어 있을 때만 해야 하는 일이다.

## 4. 작업 순서

1. **읽기** — SPEC / HANDOFF / BACKLOG / `git log` / 참조 파일
2. **만들기** — BACKLOG에서 작업 **하나만**
3. **확인** — 위 검증 명령 실행 + 합격 기준 대조
4. **커밋** — 통과 **즉시**
5. **기록** — BACKLOG / HANDOFF / JOURNAL 갱신 후 커밋

## 5. 커밋 규칙

- 검증 통과 직후 즉시 커밋. 사이에 아무 작업도 끼우지 않는다.
  → **왜**: 루프는 도중에 멈춘다. 커밋 안 된 노동은 0이다.
- 커밋 1개 = 작업 1개.
- 메시지: `<type>: <요약>` + 무엇을 왜 + `검증: <명령과 결과>` + `Task: <ID>`
- 브랜치: `<main에 직접 / feature 브랜치 이름 규칙>`
- push: `<금지 / 허용 조건>`

## 6. 막혔을 때

- 같은 작업 3회 검증 실패 → 커밋하지 말고 `[!]`로 표시, HANDOFF에 에러 원문 기록, 루프 정지
- SPEC으로 판단 불가 → 추측하지 말고 HANDOFF에 질문을 적고 정지
