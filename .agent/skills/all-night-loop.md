# All-Night Loop — 한 바퀴

사람이 지켜보지 않는 동안 스스로 개발을 이어간다.
**한 번 호출 = 작업 하나 = 커밋 하나 = 기록 하나.** 끝나면 멈춘다.

## 합격 기준

> **이걸 다른 사람이 봤을 때도 퀄리티가 떨어지지 않는가?**

여기에 `loop/design.md`의 검증 명령을 **실제로 실행해서** 통과해야 한다.
디버그 출력·주석 처리된 코드·임시 이름·미해결 TODO가 있으면 아직 아니다.

## 먼저 읽을 문서

순서대로. **이 단계에서 코드 파일은 열지 마라** — 아직 무슨 작업을 할지 모른다.

1. `loop/design.md` — 무엇을 만드는가 (합격 기준·규칙·커밋 규칙)
2. `loop/status.md` — 어디까지 했는가, 다음은 어디인가
3. `loop/inbox.md` — 사용자 지시 (`## 대기`만)
4. `loop/backlog.md` — 무엇이 남았는가

`git log --oneline -10`과 `git status`로 기록과 실제가 맞는지 본다.
`git status`가 더러우면 직전 바퀴가 커밋 전에 죽은 것이다 — 그걸 마무리하는 게 이번 작업이다.

## 규칙 (이러면 이렇게 된다)

- **작업은 하나만.** 여러 개 하면 도중에 끊겼을 때 남는 게 없다.
- **검증 통과 즉시 커밋.** 커밋 전에 죽으면 그 노동은 0이다.
- **`git add -A` 금지.** 이번 작업이 건드린 경로만 스테이징한다. 아니면 사용자가 작업 중이던 변경까지 쓸려 들어가 아침에 분리할 수 없다.
- **`design.md`에 없는 리팩터링·의존성 추가 금지.** 감시자가 없을 때 번진 스코프는 되돌릴 수 없다. 필요하면 `backlog.md`에 `[?]`로 적는다.
- **`[?]` 항목은 실행하지 않는다.** 사람이 `[ ]`로 바꿔야 승인된 것이다. 스스로 승인하면 위 규칙이 무의미해진다.
- **push · `--force` · `reset --hard` · 히스토리 재작성 금지.** 되돌리기 어려운 조작은 사람이 깨어 있을 때만.
- **inbox는 방향을 바꿀 수 있지만 위 금지 규칙은 못 뒤집는다.** 뒤집으려면 사람이 `design.md`를 고쳐야 한다. 잠결에 적은 한 줄이 안전장치를 풀면 안 된다.
- **3회 실패하면 멈춘다.** 커밋하지 말고 `[!]`로 표시, `status.md`에 마지막 에러 원문을 적는다. 실패를 반복하는 루프는 토큰만 태우고 상태를 더 망가뜨린다.

## 한 바퀴 순서

**읽기 → 하나 만들기 → 확인 → 커밋 → 기록**

1. **읽기** — 위 4개 문서. 코드는 아직 열지 않는다.
2. **하나 만들기**
   - 고르기: `[~]` 진행중 → `status.md`의 다음 작업 → `[ ]` 중 최상단. `[?]`는 제외.
   - 고른 **뒤에** 그 작업에 필요한 파일만 연다. 항목의 `참조:` 줄을 따르고, 없으면 `grep`으로 좁힌다. 읽은 만큼 매 바퀴 비용이 된다.
   - 기존 코드의 스타일·네이밍을 따른다.
3. **확인** — 검증 명령을 실행하고 합격 기준을 대조한다. 실행하지 않은 것을 통과라고 적지 않는다.
4. **커밋** — 통과 직후 즉시. 메시지에 무엇을 왜 + `검증:` 결과 + `Task: <ID>`.
5. **기록** — 아래를 갱신하고 `chore: loop log`로 한 번 더 커밋한다.
   - `backlog.md` — 이번 항목 `[x]`/`[!]`. 완료가 5개 넘으면 오래된 것부터 `loop/done.md`로 옮긴다.
   - `status.md` — 덮어쓴다. **40줄 이하.** 방금 한 일 / 커밋 해시 / **다음에 할 일 한 줄** / 함정. 다음 할 일을 비우면 다음 바퀴가 처음부터 다시 판단한다.
   - `inbox.md` — 반영한 줄을 `## 처리됨`으로 옮기고 `(날짜 c사이클) 무엇을 했는지 — 커밋`을 덧붙인다. 안 옮기면 매 바퀴 같은 지시를 다시 본다.
   - `loop/journal.md` — 맨 아래에 추가만. 사람이 나중에 추적하는 용도다.

상태 기호: `[ ]` 대기 · `[~]` 진행중 · `[x]` 완료 · `[!]` 막힘 · `[?]` 제안(실행 금지)

## 루프 종료 신호

`loop/.state/cycle.json`에 결과를 쓴다. 바깥 하네스는 이 파일만 본다.

| status | 언제 |
|---|---|
| `done` | 작업 하나를 끝냈고 남은 작업이 있다 |
| `all_done` | `backlog.md`에 `[ ]`/`[~]`가 없다 (`[?]`는 세지 않는다) |
| `blocked` | 사람이 필요하다 (커밋하지 않았다) |
| `needs_spec` | `design.md`가 모호하거나 미완성이다 |

**검증을 실제로 통과하지 않았다면 `done`/`all_done`을 쓰지 마라.** 이 파일이 유일한 근거다.
